# API agent guide

Follow the [repository guide](../../AGENTS.md) and current [README commands](../../README.md). Detailed design and work logs are maintained outside the repository; existing `docs/` records predate this API foundation.

This package contains the local Hono / Drizzle / D1 foundation and Better Auth / Passkey administrator authentication. `GET /health` reads `SELECT 1`. Authentication has five generated Better Auth models (`user`, `session`, `account`, `verification`, `passkey`) and the application-owned `bootstrap_grant` table. Migration `0001_multiple_passkeys.sql` upgrades the initial schema to allow multiple passkeys per user. Blog APIs, the admin UI, recovery, and backup-key management are not implemented. The Next.js contact API remains in `apps/web`.

- Keep the pinned dependency versions and the single root pnpm lockfile.
- Better Auth, its Passkey plugin and Drizzle adapter, and the `auth` CLI are pinned to 1.7.12; Drizzle Kit is pinned to 0.31.11. Use root `pnpm auth:schema:generate` and `pnpm db:generate`, never an unpinned or `latest` generator.
- Keep runtime and generation model options shared in `src/auth/model-options.ts`. Generate `src/auth/schema.ts` from `auth.schema.config.ts` without connecting to D1 or loading a secret. Preserve every upstream model field, snake_case SQL table/column names, camelCase TypeScript fields, unique credential IDs, and the non-unique user lookup index. Users have many passkeys; do not impose a per-user key limit. Keep the application-owned bootstrap schema separate and review generated migrations before applying them. Preserve the initial migration and apply the additive migration to existing local databases without resetting them.
- Use the local D1 binding. Its all-zero database ID is a placeholder; do not create a remote database or deploy without explicit authorization.
- Keep `workers_dev` and `preview_urls` disabled, omit public routes, and preserve `remote: false` on D1.
- Generate `ApiEnv` with root `pnpm cf-typegen:api` after binding changes; do not hand-edit `cloudflare-env.d.ts`.
- Local setup order is root `pnpm auth:setup:local`, `pnpm db:migrate:local`, then `pnpm auth:issue:local`. The setup command must never overwrite an existing `.dev.vars`. Administrator identity comes only from server configuration, never client input or an operator argument. The operator may create the configured local user, but must never insert a session directly.
- Store registration permit hashes in D1 and raw permits only in the ignored 0600 operator file. Permits expire after 10 minutes; reissue invalidates the previous unused permit. Require the permit header on both registration endpoints, recheck it during persistence, and never accept it in a URL or registration context. Preserve the D1 batch that atomically saves the first key and consumes the permit; do not replace it with separate writes or an interactive transaction.
- The initial-registration adapter must abort its D1 batch inside SQL if a saved key has no matching consumed grant, including a zero-row consumption update. Post-commit metadata checks alone cannot enforce rollback. Keep `bootstrap_grant.consumed_at` and `credential_id` as the enduring initial-registration completion record: future key deletion must not delete or clear them, and the credential reference intentionally has no cascading passkey foreign key. Do not reopen bootstrap when all passkeys are deleted.
- Once the key is saved and the permit consumed, failure to create a session is retried through ordinary login, not initial registration. Multiple stored keys can authenticate, but additional-key registration/deletion endpoints and recovery remain unavailable until that work is explicitly authorized.
- Keep the auth route/method allowlist, exact trusted origin, server-configured administrator checks, and server-side user verification. Do not expose password, signup, social-login, account-linking, or general passkey-management endpoints. DB failures must fail closed, including logout and session lookup.
- Local authentication uses `http://localhost:8788` and RP ID `localhost`. Preserve HttpOnly, SameSite=Lax, host-only cookies and every individual Set-Cookie header. Secure cookies are required by the production configuration branch; its final domain and deployment remain unvalidated. Local session settings are 8 hours with a 1-hour update interval and cookie cache disabled; the pinned Passkey plugin uses 5-minute challenges. These do not establish a finalized production session policy.
- Keep database failures and environment values out of responses and logs.
- Run `pnpm lint`, `pnpm typecheck`, `pnpm test`, and `pnpm build` in this package. The build command only performs a local Wrangler dry run.
- Tests use Wrangler's local test harness and real local D1. The root authentication E2E uses a test-only browser fixture and virtual authenticator; never ship its entry page or persist cookies, permits, credentials, or secrets in test artifacts. Failure-path tests must not add production-only test switches or contact external services.
